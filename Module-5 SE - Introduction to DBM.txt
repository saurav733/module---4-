1. Introduction to SQL

Q1. What is SQL, and why is it essential in database management?
SQL (Structured Query Language) is the language used to talk to databases.
It helps us create tables, insert data, update, delete, and search easily.
Without SQL, handling large data in DBMS would be very hard.

Q2. Explain the difference between DBMS and RDBMS.

DBMS: General system to manage data. Data may not be in tables (can be files, hierarchy, etc.). Example: MS Access.

RDBMS: Special DBMS where data is stored in tables (rows and columns) and relations between them. Example: MySQL, Oracle.

Q3. Describe the role of SQL in managing relational databases.
SQL allows us to create, store, modify, and retrieve data in RDBMS.
It is like a bridge between user and database.

Q4. What are the key features of SQL?

Easy to learn and use.

Can handle large data.

Supports queries, updates, and transactions.

Works with multiple tables using JOIN.

Standard language supported by most databases.

2. SQL Syntax

Q1. What are the basic components of SQL syntax?

Keywords (SELECT, INSERT, CREATE, etc.)

Clauses (WHERE, ORDER BY)

Expressions (calculations, conditions)

Statements (complete commands like SELECT * FROM students;)

Q2. Write the general structure of an SQL SELECT statement.

SELECT column1, column2
FROM table_name
WHERE condition
ORDER BY column;


Q3. Explain the role of clauses in SQL statements.
Clauses add extra meaning to queries.

WHERE → filter rows

ORDER BY → sort data

GROUP BY → group rows

HAVING → filter groups

3. SQL Constraints

Q1. What are constraints in SQL? List and explain types.
Constraints = rules applied on table columns to keep data correct.
Types:

NOT NULL → value cannot be empty.

UNIQUE → no duplicate values.

PRIMARY KEY → unique + not null, identifies each row.

FOREIGN KEY → links two tables.

CHECK → condition must be true (ex: Age > 0).

DEFAULT → auto value if nothing is entered.

Q2. How do PRIMARY KEY and FOREIGN KEY differ?

Primary Key: unique id for a row in a table.

Foreign Key: column that refers to primary key of another table (creates relation).

Q3. What is the role of NOT NULL and UNIQUE constraints?

NOT NULL → makes sure value is always given.

UNIQUE → makes sure all values in that column are different.

4. Main SQL Commands and Sub-commands (DDL)

Q1. Define the SQL Data Definition Language (DDL).
DDL = part of SQL used to define and change structure of database objects like tables, views, indexes.

Q2. Explain the CREATE command and its syntax.
CREATE is used to make a new table, database, or object.
Example syntax:

CREATE TABLE students (
   student_id INT PRIMARY KEY,
   name VARCHAR(50),
   age INT
);


Q3. What is the purpose of specifying data types and constraints during table creation?

Data types (INT, VARCHAR, etc.) tell what kind of values will be stored.

Constraints (NOT NULL, UNIQUE, etc.) keep data correct and valid.

5. ALTER Command

Q1. What is the use of the ALTER command in SQL?
ALTER is used to change an existing table → add, remove, or modify columns.

Q2. How can you add, modify, and drop columns from a table using ALTER?

Add column:

ALTER TABLE students ADD email VARCHAR(50);


Modify column:

ALTER TABLE students MODIFY age INT;


Drop column:

ALTER TABLE students DROP COLUMN age;

6. DROP Command

Q1. What is the function of the DROP command in SQL?
DROP is used to delete a table or database permanently from DB.

Q2. What are the implications of dropping a table from a database?

All data inside table is lost.

Table structure is removed.

Cannot be recovered unless you have backup.


7. Data Manipulation Language (DML)

Q1. Define the INSERT, UPDATE, and DELETE commands in SQL.

INSERT → used to add new rows of data.

UPDATE → used to change existing data.

DELETE → used to remove rows from table.


Q2. What is the importance of the WHERE clause in UPDATE and DELETE operations?
WHERE makes sure only specific rows are updated/deleted.
If you skip WHERE, all rows will be changed!

8. Data Query Language (DQL)

Q1. What is the SELECT statement, and how is it used to query data?
SELECT is used to fetch data from tables. Example:

SELECT name, age FROM students;


Q2. Explain the use of the ORDER BY and WHERE clauses in SQL queries.

ORDER BY → arranges data ascending/descending.

WHERE → filters data by condition.

9. Data Control Language (DCL)

Q1. What is the purpose of GRANT and REVOKE in SQL?

GRANT → gives permission (like SELECT, INSERT).

REVOKE → removes permission.

Q2. How do you manage privileges using these commands?
Admin uses GRANT to allow users access and REVOKE to take it back. Example:

GRANT SELECT ON students TO user1;
REVOKE INSERT ON students FROM user1;

10. Transaction Control Language (TCL)

Q1. What is the purpose of the COMMIT and ROLLBACK commands in SQL?

COMMIT → permanently saves changes.

ROLLBACK → undo changes since last COMMIT.

Q2. Explain how transactions are managed in SQL databases.
 A transaction is a group of SQL operations.
It follows ACID properties (Atomicity, Consistency, Isolation, Durability).
We can control them using COMMIT, ROLLBACK, and SAVEPOINT.

11. SQL Joins

Q1. Explain the concept of JOIN in SQL. What is the difference between INNER JOIN, LEFT JOIN, RIGHT JOIN, and FULL OUTER JOIN?

JOIN → used to combine data from multiple tables.
Types:

INNER JOIN → only matching rows.

LEFT JOIN → all rows from left table + matching from right.

RIGHT JOIN → all rows from right table + matching from left.

FULL OUTER JOIN → all rows from both tables.

Q2. How are joins used to combine data from multiple tables?
 Joins use common columns (keys) to merge rows from two or more tables.

12. SQL GROUP BY

Q1. What is the GROUP BY clause in SQL? How is it used with aggregate functions?
GROUP BY groups rows with same value.
With aggregate functions (COUNT, SUM, AVG) it gives group-wise results.

Q2. Explain the difference between GROUP BY and ORDER BY.

GROUP BY → groups rows into sets.

ORDER BY → sorts rows.

13. SQL Stored Procedure

Q1. What is a stored procedure in SQL, and how does it differ from a standard SQL query?
Stored procedure = a set of SQL commands stored in DB.
It can be reused. A normal query runs once, but procedure can be called many times.

Q2. Explain the advantages of using stored procedures.

Saves time (reusable).

Improves security (hide SQL logic).

Faster execution.

Easier to maintain.

14. SQL View

Q1. What is a view in SQL, and how is it different from a table?
View = virtual table based on a query.
It does not store data physically, just shows it from original table.

Q2. Explain the advantages of using views in SQL databases.

Provides security (hide sensitive columns).

Simplifies queries.

Shows only required data.

15. SQL Triggers

Q1. What is a trigger in SQL? Describe its types and when they are used.
Trigger = automatic action when an event happens (INSERT, UPDATE, DELETE).
Types:

BEFORE Trigger

AFTER Trigger

INSTEAD OF Trigger

Q2. Explain the difference between INSERT, UPDATE, and DELETE triggers.

INSERT Trigger → runs when new row is added.

UPDATE Trigger → runs when row is modified.

DELETE Trigger → runs when row is removed.

16. Introduction to PL/SQL

Q1. What is PL/SQL, and how does it extend SQL's capabilities?
PL/SQL = Procedural Language extension of SQL.
It adds loops, conditions, variables to SQL → makes it more powerful.

Q2. List and explain the benefits of using PL/SQL.

Faster execution (batch processing).

Supports programming features.

Easy error handling.

Can create procedures, functions, triggers.

17. PL/SQL Control Structures

Q1. What are control structures in PL/SQL? Explain the IF-THEN and LOOP control structures.
Control structures = decision-making & looping tools.

IF-THEN → run code only if condition is true.

LOOP → repeat code multiple times.

Q2. How do control structures in PL/SQL help in writing complex queries?
They let us add logic (conditions + loops), so we can solve bigger tasks (like checking records one by one).


18. SQL Cursors

Q1. What is a cursor in PL/SQL? Explain the difference between implicit and explicit cursors.
Cursor = pointer that lets us go row by row in a query result.

Implicit cursor → auto-created when a query runs.

Explicit cursor → programmer defines it for more control.

Q2. When would you use an explicit cursor over an implicit one?
 Use explicit cursor when:

You need to process rows one by one.

You need more control (fetch, close, etc.).


19. Rollback and Commit Savepoint

Q1. Explain the concept of SAVEPOINT in transaction management. How do ROLLBACK and COMMIT interact with savepoints?

SAVEPOINT → marks a point inside a transaction.

ROLLBACK TO SAVEPOINT → undo only till that point.

COMMIT → saves everything permanently.

Q2. When is it useful to use savepoints in a database transaction?
 When you are doing multiple operations and want to undo only some part, not the whole transaction. Example: inserting 100 rows, rollback only last 10.
